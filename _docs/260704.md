# 260704: アシスタント感向上 — sense キック + DB 補足情報 + 任意タイミング注入

## ゴール

Tomoko が「MCP 的に」任意のタイミングで裏の感覚(スクリーンショット、world 検索、カメラ presence)を
キックし、結果を DB に保持して、会話の任意のタイミングでプロンプト/発話に載せられるようにする。

既存の骨格(5秒 tick の info/think/summary プロセス、v2_candidates → VOLATILE_RECALL、
OCR user_status、poll_orders 継続発話レーン)は活かし、**push 一辺倒のパイプラインに
pull(キック)と retrieval を足す**。

## 実装順(上から順に実装する)

### 1. sense_request 基盤(DB テーブル + bridge SQL)
- `docker/postgres/init/101_v2_sense.sql`: `v2_sense_requests`
  (id, kind, query, trace_id, status=pending/claimed/done/failed, result jsonb, requested_at/claimed_at/completed_at)。
- `db_bridge.py`: insert / claim(FOR UPDATE SKIP LOCKED)/ complete / load ヘルパ。
- 既存 dev DB へは init SQL を手動適用(init script は新規 volume でのみ走るため)。
- 受け入れ: integration テストで insert→claim→complete→load が回る。

### 2. 会話コアからのキック + 即答 + 結果の継続発話
- `TomokoConversationCore` に `sense_executor`(注入可能な Callable)を追加。
  final 発話に screenshot キュー(「画面」「見て」「何してる」等)を検出したら
  sense_request を発行し、即答オーダー(「ちょっと画面見てみるね。」)を返す。
- 結果待ちはバックグラウンドタスク: sense 完了(または timeout)後、結果を
  RUNTIME_CONTEXT に載せた LLM 呼び出しで続きを生成し `_pending_followup_orders` へ。
  → 既存の poll_orders レーンで hot-path が回収して append 発話(hot path 無停止)。
- realtime 側は DB-backed sense_executor を注入。fake runtime は env fixture の fake executor。
- 受け入れ: fake シナリオ `sense-screenshot-followup` が suite で PASS
  (即答 replace → sense 結果を含む followup append)。

### 3. user-status worker がスクショ sense を消化
- `run_process("user-status")` に tick を追加:
  pending screenshot sense_request を claim → `capture_ocr_observation_once()`
  → `v2_user_status_observations` insert + sense_request complete(result に activity/summary/ocr 抜粋)。
- あわせて定期受動キャプチャ(env `TOMOKO_V2_USER_STATUS_INTERVAL_SEC`、0 で無効)。
- `db_bridge.py` に insert_user_status_observation_sql を追加。
- 受け入れ: unit(claim→complete の流れを fake capture で)+ 実機で
  sense_request 発行→ user-status プロセスが consume → done を確認。

### 4. query-driven recall(発話に関連する記憶の注入)
- realtime の final 処理時に basis テキストを埋め込み、
  summaries / world interpretations と cosine 類似で top-k を snapshot に注入
  (現状の「最近8件」を「関連k件+最近数件」に変更)。
- 埋め込みは既存 `summary/main.py embed_text`(8次元 char バケット)を
  文字 bigram ベースに強化して共有化。※本物の埋め込みモデル導入は別タスク(TODO)。
- 受け入れ: unit で「関連する summary が非関連より上位に注入される」こと。

### 5. world 検索 worker の実体化(プラガブル / MCP 接続点)
- info tick: fixtures に加えて sense_request(kind=world_search) を claim し、
  プラガブル backend(env `TOMOKO_V2_WORLD_SEARCH_CMD`: query を渡して JSON を返す任意コマンド。
  将来ここに MCP クライアントを接続)で検索 → v2_world_documents/items/interpretations へ。
  think が既存ロジックで candidates 化 → VOLATILE_RECALL / initiative に乗る。
- 受け入れ: fake backend(echo JSON)で sense_request → candidates 化まで integration で確認。

### 6. カメラ presence(在/不在)
- `scripts/camera_presence/CameraPresence.swift`: AVFoundation で1フレーム取得
  → Vision 顔検出 → JSON(present, confidence)。STT/OCR サイドカーと同パターン。
- user-status tick が env `TOMOKO_V2_CAMERA_PRESENCE=1` のとき定期実行し、
  source="camera" の user_status observation を DB へ。presence は既存の
  world materials 経由で initiative 抑制/deliverability に効く。
- 受け入れ: サイドカー単体で JSON が返る + observation が insert される。

## 検証

各ステップで `make check` + 関連 unit。2 完了時に fake シナリオ追加、
3 完了時に実機(hot-path + realtime + user-status)で E2E、
最後に `make v2-scenario-suite` + real replay + latency suite の回帰。

## Perplexity 検索バックエンド(実装済み)

- `scripts/world_search_perplexity.py` が `tomoko-research-operator`
  (CDP Chrome :9000 + ログイン済み Perplexity)を包むアダプタ。
  ResearchResult JSON → `{"items":[{"text": "...(出典: ...)"}]}` に変換、
  operator の flaky に備えて 1 回リトライ(`TOMOKO_RESEARCH_RETRIES`)。
- Makefile 既定: `TOMOKO_V2_WORLD_SEARCH_CMD ?= python3 scripts/world_search_perplexity.py`
  (v2-tomoko / v2-info に配線済み)。
- タイムアウト: world_search の sense 待ちは 120s(`TOMOKO_V2_WORLD_SEARCH_SENSE_TIMEOUT_SEC`)、
  worker の subprocess は 150s、hot-path の followup poll は最長 140s。
- 検索が失敗/空のときは「ごめん、うまく調べられなかったよ。」を append して黙らない。
- real E2E 実測: 「調べて」発話 → 相槌 3.9s → 「ちょっと調べてみるね。」5.3s →
  Perplexity 検索 17.4s → 結果を踏まえた followup 発話 28.2s。
- 前提: CDP Chrome(:9000, `~/.chrome-tomoko-research`)が起動し Perplexity にログイン済みであること。

## 実行時の権限メモ

- スクショ sense: tmux を起動しているターミナル App に「画面収録」権限が必要
  (未許可だと screencapture が失敗し、OCR 空文字で followup が薄くなる)。
- カメラ presence: 同ターミナル App に「カメラ」権限が必要
  (未許可はサイドカーが graceful に失敗し、observation は書かれない)。

## 追加で入れた挙動ガード

- partial start gate に yield チェックを追加: ユーザーが話し続けている
  (speech_probability>0.3 かつ p_yielding<0.5 かつ silence<300ms)間は
  フル返信レーンの先行生成を止め、相槌(ack レーン)に任せる。
  発話途中にフル返信が割り込んで VAD セグメントが濁る real 回帰を修正。
