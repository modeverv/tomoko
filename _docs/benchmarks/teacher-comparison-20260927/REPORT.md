# Gemma / Codex 教師比較（2026-09-27）

今回の人工例では、Codex 教師は事前期待への一致が高かったが、同じ hash-ridge 学生へ蒸留した後の改善は最大で 1/76 件だった。Codex による採点は速くならなかった。runtime の既定モデルは変更していない。

**以下は別の Codex エージェントが教師出力を見る前に作った人工例の期待値との一致率であり、人間の正解や実会話精度ではない。同系統モデルを優遇するバイアスがある。**

## 条件

- 新規の人工日本語 240 件。学習 160 件 / 評価 80 件、発話状況 120 group。group と本文の train/eval 重複なし。評価の曖昧な 4 件を除き、ready 38 / wait 38 の 76 件で二値集計。
- 対象は「会話相手が今返し始めてよい度合い」。音声として話し終わったかの判定ではない。
- Gemma: この checkout の既存 fused Gemma 4 26B A4B 4bit、MLX。過去の base checkpoint そのものではなく、DFlash も使っていない。
- Codex: gpt-6-astra / reasoning medium / CLI 0.154.0。現在のユーザー設定のモデルを使用。他の設定を読み込まず、ツールを使わない隔離した採点。
- 両者に完全一致の prompt / input order / 短いバッチ内 ID を渡した。20 件ずつ、12 batch。参照ラベル・カテゴリ・未来の続きを渡していない。
- 学生は既存の文字 1–4 gram + Ridge。両教師とも同じ 160 件のみで学習し、手作り anchor は加えていない。is_final=True を全件固定し、コーパスの終端情報を漏らさない。閾値 0.75、設定は採点前に固定。
- Apple M4 Max / 128 GiB。比較用 Gemma サーバーは計測後停止。実会話・私的ログ・JDD は外部送信していない。

## 評価結果

| 条件 | 一致件数 / 76 | 一致率 | 待つべき例で応答可 | 応答可の例で待つ |
|---|---:|---:|---:|---:|
| Gemma 教師 | 72/76 | 94.7% | 1/38 | 3/38 |
| Codex 教師 | 76/76 | 100.0% | 0/38 | 0/38 |
| Gemma 学生: 2048 / λ1 | 45/76 | 59.2% | 0/38 | 31/38 |
| Codex 学生: 2048 / λ1 | 45/76 | 59.2% | 0/38 | 31/38 |
| Gemma 学生: 現行と同じ 8192 / λ0.01 | 61/76 | 80.3% | 0/38 | 15/38 |
| Codex 学生: 現行と同じ 8192 / λ0.01 | 62/76 | 81.6% | 0/38 | 14/38 |
| 既存公開モデル（別データ学習・補正前） | 42/76 | 55.3% | 5/38 | 29/38 |

主条件 2048 / λ1 は両方とも 45/76 件。事前に固定した現行相当設定でも 61/76 対 62/76 件で、Codex 学生の改善は 1 件（1.3 percentage points）。その内訳は 3 件改善・2 件悪化で、教師の優位性が学生にそのまま移るとは言えない。

既存公開モデルは教師 160 件に手作り anchor 4,000 件などを加えて学習した別モデルであるため、教師交換の因果比較には使わない。ここでの数値は raw scorer 単体であり、runtime の short-ack 補正や発話 gate、音声信号を含む会話全体の評価ではない。

## 時間

| 計測 | Gemma 教師系 | Codex 教師系 |
|---|---:|---:|
| 240 件の採点 wall time | 129.302 秒 | 136.843 秒 |
| 学習用 160 件の採点 batch 合計 | 77.222 秒 | 94.907 秒 |
| Ridge 学習中央値: 2048 / λ1 | 48.943 ms | 48.830 ms |
| Ridge 学習中央値: 8192 / λ0.01 | 2.211 秒 | 2.028 秒 |
| 常駐予測平均: 8192 / λ0.01 | 0.227 ms | 0.226 ms |

採点は20件バッチのCLI/HTTP処理込み。1件あたりに割った値は償却時間で、オンラインの1回応答レイテンシではない。Codex はエージェント用 system prompt と CLI overhead を含むため、基盤モデル単体の速さの比較でもない。最初の起動・warmup・失敗した試行はこの表から分離した。
Ridge は反復学習ではなく同じ形の線形方程式を解くため、教師を賢くしても計算量は変わらない。各3回を交互順で測定したが、8192版は Gemma 1.75–3.92秒 / Codex 1.79–2.69秒とばらつき、学習が速くなった証拠とは扱わない。常駐予測は100回warmup後に評価80文を巡回して1000回計測。

## 教師で差が出た4例

| テキスト | 事前期待 | Gemma | Codex |
|---|---|---:|---:|
| 椎茸を干そうと並べたのはいいけれど、雨なら室内でも干せる | 応答可 | 0.30 | 0.85 |
| 糸が針の穴に通らないので、拡大して見える | 待つ | 0.85 | 0.22 |
| プラネタリウムは初めてなんだけど、途中で外に出られるの | 応答可 | 0.40 | 0.95 |
| 鉛筆で下書きはしたものの、色の組み合わせを決められない | 応答可 | 0.30 | 0.82 |

Gemma は「けれど」「なんだけど」「ものの」を含む後半まで完結した例でも低く採点した。一方、Codex は今回の期待と一致した。ただし教師の1例の改善が、そのまま同じ例の学生改善になるわけではない。例えば鉛筆の例は、Gemma学生0.751 / Codex学生0.666で逆転した。文字特徴・少数データ・スコア較正の影響を分離する必要がある。

## 形式失敗と再試行

最初の長いhex IDを使ったGemmaの20件は、1文字欠落によるID不一致で15.0秒後に失敗。全件不採用とし、補正やheuristic fallbackはしていない。同形式のCodexは240件を完走した。両者を短いバッチ内IDに変更して同条件で全件やり直し、上表はこの再実行のみを使う。試行を含めた開発作業全体の時間短縮を示す表ではない。

## 判断

- Codex を教師にすると、日本語の境界例でラベルを改善できる可能性は見えた。ただしAI作成の参照なので、人間確認前に精度向上とは断定しない。
- この160件の学習では、教師交換だけで学生精度を大きく上げる結果にはならなかった。現在の文字特徴、学習件数、ラベルのスケール、閾値が制約になっている可能性があるが、この実験だけで原因は特定できない。
- 今回は教師採点の所要時間も短縮していない。runtime でのローカル推論速度は両者ほぼ同じ。
- 採用前には差の出た例を人間が確認し、実会話はローカルのまま別評価する。評価セットを調整に使う場合は、新しい未見セットを作る。
