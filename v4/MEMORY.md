### P1 の判断（2026-11-10）
- 引き金に `after_reply` を足した。ARCHITECTURE 5.2 には `at` と `after_tomoko_speaks` しかないが、複数ターン（C2）で「返事が終わってから次を言う」が要る。返事がなくても必ず流れるので、無応答は前提不成立ではなく失敗になる。
- 偽のシステムに「礼儀正しい」を足した。3 つだけでは、止まる側の採点（T4 の停止、T3 の中断）に正の例がない。
- 「早すぎ」を 2 つに分けた。ユーザーが話している間に**始めた**のが「早すぎ」、ユーザーが話し始めても**譲らなかった**のが「かぶせ続けた」。分けないと、ユーザーが割り込んだ回まで Tomoko の早すぎに数えてしまう。
- 言いよどみの割り込みは、「その間に始めた」も数える。重なりだけで見ると、無音の終わり際に話し始めた回を落とす。
- 時計じかけは、入力の注釈を読まず、音量で言い終わりを見る。0.5 秒の無音で話す素朴な作りなので、言いよどみにも割り込む。P2 の基準線（無音 400 ms で言い終わり）も同じ振る舞いになるはず。
- 採点役は `claude-opus-5-5`、effort は low にした。小の組 1 回で 40 件ほどの呼び出しになる。

### 気づき

- Python の SDK は、`ant auth login` のサインインをそのまま使えた（鍵なしで採点役を呼べた）。

## 2026-11-13（Codex）: 1 回合成の作業開始時の気づき

- この worktree の `.venv` には、単体テストが import する `httpx` がない。変更前から全体テストの収集が 4 ファイルで失敗する。ネットワークと uv sync は今回のユーザー指示で禁止されているため、外部取得はしない。

### 1 回合成の注釈の境界（実装中の気づき）
- 要求した無音の 80% をサンプル数に四捨五入すると、端数を持つ要求では 80% 未満を許してしまう。必要サンプル数は切り上げ、表示用の秒の丸めより前に判定する。浮動小数点の境界誤差だけは 1e-9 サンプルの許容を置く。
- voiced の短いすき間をつなぐ前の音量区間から pause 候補を取る。0.15 秒未満の pause も、voiced の結合とは別に検出できる。

### 確定した判断: 既定の入力を保つ追加方式
- ユーザー依頼を実装し、`--one-pass` を付けたときだけ `[[slnc ms]]` を埋めた 1 回合成へ切り替える。`Manifest.one_pass` は `private` の後に既定値 False で追加し、古い JSON と位置引数を保つ。
- キャッシュの既定キー `voice|text` は維持し、1 回合成だけ `one-pass|voice|text` にする。保存前の正規化・前後の無音除去・16 kHz PCM は共通の処理を使う。
- 注釈の振幅閾値は 0.005、voiced の結合は 0.15 秒未満。pause は内部無音の長い順から選び、時刻順に戻して要求長と照合する。先頭・末尾の無音は選ばない。句点の自然な間を人為的に短くしない。
- 小数の下限の回帰テストを加えた後、独立した Codex（gpt-6.1-sol、max）の読み取りレビューで残る確定問題はなかった。レビューにはコードと合成データだけを渡した。

### 検証環境と実音声の制限
- 不足した httpx と依存は、同じ機械の既存 v4 仮想環境からこの worktree の `.venv` にコピーした。外部取得・uv sync・ロックファイル変更はしていない。
