### P1 の判断（2026-11-10）
- 引き金に `after_reply` を足した。ARCHITECTURE 5.2 には `at` と `after_tomoko_speaks` しかないが、複数ターン（C2）で「返事が終わってから次を言う」が要る。返事がなくても必ず流れるので、無応答は前提不成立ではなく失敗になる。
- 偽のシステムに「礼儀正しい」を足した。3 つだけでは、止まる側の採点（T4 の停止、T3 の中断）に正の例がない。
- 「早すぎ」を 2 つに分けた。ユーザーが話している間に**始めた**のが「早すぎ」、ユーザーが話し始めても**譲らなかった**のが「かぶせ続けた」。分けないと、ユーザーが割り込んだ回まで Tomoko の早すぎに数えてしまう。
- 言いよどみの割り込みは、「その間に始めた」も数える。重なりだけで見ると、無音の終わり際に話し始めた回を落とす。
- 時計じかけは、入力の注釈を読まず、音量で言い終わりを見る。0.5 秒の無音で話す素朴な作りなので、言いよどみにも割り込む。P2 の基準線（無音 400 ms で言い終わり）も同じ振る舞いになるはず。
- 採点役は `claude-opus-5-5`、effort は low にした。小の組 1 回で 40 件ほどの呼び出しになる。

### 気づき
- macOS の `say` の日本語は、Kyoko 以外の 4 つ（Flo、Eddy、Sandy、Reed）が同じ長さの音を返した。声色が違うだけで、話し方は同じ系統と思われる。話者の多様さとしては弱い。
- 合成の声は、文の切れ目で 0.5 秒を超えて黙ることがある。無音だけで言い終わりを決める方式は、合成の入力でも早すぎが出る。
- Silero VAD は、声の頭を 0.02〜0.05 秒遅く、終わりを最大 0.1 秒ほど遅く出した。
- Python の SDK は、`ant auth login` のサインインをそのまま使えた（鍵なしで採点役を呼べた）。

### 未解決の疑問
- 遅れの誤差（+0.022〜+0.047 秒）を受け入れるか。受け入れるなら、関門の条件を「0.05 秒以内」に改める。受け入れないなら、VAD の代わりに音量で開始を取るなどの案がある。
- 短い反応と本発話の境（1.0 秒）は妥当か。途中で止まった本発話を短い反応に数えてしまう。
- `say` の声は公開できず、話し方も 2 系統しかない。入力の合成を Kokoro に替えるか。
