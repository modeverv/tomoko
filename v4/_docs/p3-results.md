## 1. 進め方

## 4. MaAI の下調べ（言い終わりの判定）

`scripts/maai_offline.py`。基準線 1 回目の入力音声 45 件（T1、T2、C2、T5）を MaAI（vap、jp、10 Hz、CPU）に通し、無音の始まりから 0.1〜0.4 秒後の出力（Tomoko 側の `p_now`、`p_future`）を比べた。Tomoko 側の声は無音として与えた。

| 途中の無音の種類 | 件数 | 言い終わり 45 件との分かれ方（AUC、p_now、0.2 秒後 / 0.4 秒後） |
|---|---|---|
| T2 の言いよどみ | 16 | 0.78 / 0.78 |
| T5 の長い語りの、文と文の間 | 31 | 0.43 / 0.47 |
| C2 の、文と文の間 | 3 | 0.50 / 0.49 |
| 全部 | 52 | 0.55 / 0.57 |

- 言いよどみ（「えっと…」のあと）は、ある程度分かれる。文と文の間は分かれない（0.5 が当てずっぽう）。
- 無音 0.4 秒を待たずに「言い終わり」と決められる根拠は、この測り方では出なかった。
- 限界: 入力は合成音声。文末ごとに言い切りの調子で読まれるので、人の語りより不利な可能性がある。人の声では未測定。
- 処理は実時間の 0.06 倍で、CPU で足りる。
- T5 の遮りと C2 の早すぎは、割り込みの仕組み（3 節）で 0 になった。**MaAI を足しても、いまの台本では点が動く余地がほとんどない。** 入れるかどうかは人間が決める。

## 5. 分かったこと・未検証のこと

- VOICEVOX が LLM と同時だと遅くなる原因は未検証。VOICEVOX は CPU を 6〜7 コア使い、LLM のサーバーは CPU を 0.6 コアしか使わず、コアは 16 あるので、コアの取り合いではない。メモリの帯域の取り合いという推測は、切り分けの試験をしていない。
- 逐次合成の VOICEVOX を、主の Mac で LLM と同時に動かした場合の速さは測っていない。
- 「LLM は 3060、TTS は MBP の逐次合成」の組み合わせは、3060 が応答しなくなったため測っていない。
- VOICEVOX の声の聴取（人間）はまだ。

## 6. 再現の手順

```
tmux new -d -s v4-voicevox '/Applications/VOICEVOX.app/Contents/Resources/vv-engine/run --port 50021'
tmux new -d -s v4-tunnel 'ssh -N -L 18090:127.0.0.1:8090 -L 18091:127.0.0.1:8091 win'
tmux new -d -s v4-tunnel-mbp 'ssh -N -L 50122:127.0.0.1:50122 seijiro@192.168.11.34'
bash scripts/p3_latency_queue.sh   # p3-1〜p3-5
bash scripts/p3_stream_queue.sh    # p3-6〜p3-8
uv run python scripts/maai_offline.py work/runs/baseline-1 --out _docs/data/maai-offline.json
```

設定は `TOMOKO_<項目名>` の環境変数で切り替える（`engine/dto.py` の `EngineConfig`）。既定は VOICEVOX（50021 番）で、ほかは P2 と同じ。
