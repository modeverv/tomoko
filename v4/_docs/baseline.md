## 1. 何を測ったか

- 経路: Silero VAD（無音 400 ms で言い終わり）→ mlx-whisper large-v3-turbo → Gemma 4 E4B 4bit（`mlx_lm.server`、思考なし）→ Kokoro（kokoro-mlx、声 jf_alpha）。
- 割り込まれても止まらない。相づちは打たない。発話は順番に処理する。
- 1 台（Mac）で全部を動かした。MLX の処理は 1 本のスレッドに並べた。
- 小の組 55 件を、同じ構成で 3 回流した。接続の失敗は 3 回とも 0 件、無音の回 0 件、前提不成立 0 件。

### 幅の読み方

P3 以降は「幅を超える差」だけを改善または悪化と数える。この 3 回から言えるのは次のとおり。

- 遅れの中央値は 0.13 秒ほど揺れる。90% 点と、割り込み後の遅れは 0.35〜0.45 秒揺れる。
- 割合の指標は、各軸 10 件なので 1 件で 0.1 動く。T2 と T3 は 3 回で 2 件ぶん揺れた（揺れた台本は t2-08、t2-09、t3-06、t3-08）。**小の組では、T2・T3 の 0.2 以内の差は判断に使えない。**
- 3 回では幅の見積もりとして少ない。P3 の変更ごとにも 3 回流し、幅を足して見直す。

## 3. 数字の読み方で注意すること

- **T4 の「止まった割合 0.8」は、止めたのではない。** この経路は割り込まれても止まらない。返事が短く、たまたま 2 秒以内に言い終わった回が「止まった」に数えられている（定義書 5 節の既知の限界）。停止の遅れ 1.3 秒も同じで、言い終わりまでの時間である。
- **T3 の割り込み率が低いのも、止まらないから当然。** 0.1〜0.2 は、発話がたまたまそこで終わった回。
- **T5 の短い反応 0.737 回/分は、相づちではない。** 1 秒未満の短い返事が、ユーザーの発話に被ったもの。本発話でユーザーを遮った回数が 5 件で 42 回あり、長い語りの途中の無音ごとに返事を始めている。
- **C2 の早すぎ 0.4〜0.5** は、複数の文からなる発話を、文の間の無音（400 ms 以上）で切って答え始めたもの。
- C2 の誤答 2 件は 3 回とも同じ台本（c2-02、c2-06）。c2-02 は「歯医者」を「会社」と聞き違え、時刻を答えなかった。c2-06 は返事が意味の取れない断片だった。
- C1 の低い点は T4 に集まる。訂正の前の話題を話し続けてから切り替える（t4-04、t4-05）、要求に答え切らない（t4-02、t4-07、t4-08）。

## 4. 遅れの内訳（T1、言い終わりから声が出るまで）

`scripts/latency_breakdown.py` で、エンジンの記録と採点結果を突き合わせた。各 10 件の中央値（ms）。

| 区間 | 1 回目 | 2 回目 | 3 回目 | 中身 |
|---|---|---|---|---|
| vad | 450 | 450 | 450 | 無音 400 ms を待つ + VAD の刻み |
| stt | 315 | 319 | 322 | 発話全体を 1 回で認識 |
| llm | 171 | 176 | 230 | 最初の文字が出るまで |
| phrase | 153 | 182 | 151 | 最初の句がそろうまで |
| tts | 767 | 726 | 872 | 最初の句の合成（最小 258、最大 2,640） |
| deliver | 1 | −9 | −1 | 送信 |
| onset | 294 | 288 | 288 | 合成音の頭の無音 + 採点側の検出 |
| 合計 | 1,950 | 2,055 | 2,222 | |

- **いちばん大きいのは TTS（0.7〜0.9 秒）。** 最初の句を丸ごと合成してから送っている。句が長いと 1.4〜2.6 秒かかる。
- 次が VAD の待ち（0.45 秒）、STT（0.32 秒）、合成音の頭の無音（0.29 秒）。
- LLM は 0.17〜0.23 秒で、遅れの主因ではない。
- 早すぎた回は記録との対応がずれるので、最小・最大には異常値が混じる（onset の負の値など）。中央値だけを使う。

## 5. 気づいたこと（未検証を含む）

- **Kokoro の日本語の発音が崩れている疑いがある。** 出力音声を Whisper で書き起こすと、「ながら」→「なあら」、「ヨーグルト」→「ヨウルト」、「今日」→「王」、「時間」→「痴漢」のように、ガ行や一部の音が落ちている。句の終わりに「いい」「ひー」のような余分な音も付く。Whisper 側の聞き違いの可能性もあるので、**人間が聴いて確かめる必要がある**（`work/runs/baseline-1/t1-07/output.wav` など）。原因は未検証（読みの変換の段か、声 jf_alpha か）。
- 採点役は、こうした誤変換を「書き起こしのノイズ」として読み飛ばして採点している。内容の点は、発音の崩れを反映していない。
- STT の聞き違い（歯医者→会社、シチュー→支柱）が、内容の失点に直結している。

## 6. STT の途中認識（P3 の下調べ）

話している途中に 250 ms ごとに認識し直す方式を、20 発話で測った（`scripts/stt_partial_bench.py`）。

| モデル | LLM の負荷 | 1 回の認識 中央値 / 95% 点（ms） | 250 ms に間に合った割合 | 途中で書き換わった割合 |
|---|---|---|---|---|
| large-v3-turbo | なし | 617 / 910 | 0% | 33% |
| large-v3-turbo | あり | 856 / 1,146 | 0% | 33% |
| small | なし | 206 / 371 | 66.5% | 38% |
| small | あり | 412 / 850 | 8.6% | 38% |

- この Mac 1 台では、turbo の途中認識は 250 ms の刻みに間に合わない。small は単独なら間に合うが、LLM と同時だと間に合わない。
- 途中の結果が最終と一致するのは、中央値で言い終わりの 0.01 秒前。**途中認識を「先に文面を知る」ために使っても、ほとんど先回りできない。**
- 1 回の認識が 7〜22 秒かかる外れ値があった（原因は未検証）。

## 7. P3 で試す候補（1 つずつ）

遅れの内訳から、効きそうな順に並べた。順番と目標の数字は人間が決める。

1. **TTS の最初の句を短くする / 合成しながら送る**（0.7〜0.9 秒の区間）。
2. **合成音の頭の無音を切る**（0.2〜0.3 秒）。
3. **言い終わりの判定を MaAI に替える**（VAD の待ち 0.45 秒を縮め、同時に C2 の早すぎと T5 の遮りを減らす）。
4. **割り込みで止める**（T4、T3 が初めて意味を持つ）。
5. **相づち**（T5）。
6. **STT を RTX 3060 に出す**（v3 の実測: whisper.cpp turbo q5_0 が単独で中央値 186 ms、Gemma と同時で 484 ms）。設定で切り替える選択肢とし、既定にはしない。マイクの音声が LAN を流れる点は人間の確認が要る。
7. **TTS の差し替え**（発音の崩れが聴取で確かめられた場合）。
8. Apple の音声認識を常駐の補助プログラムで使う案（未測定）。

## 8. 再現の手順

```
tmux new -d -s v4-llm 'uvx --python 3.12 --from mlx-lm mlx_lm.server --model mlx-community/gemma-4-E4B-it-4bit --host 127.0.0.1 --port 8090'
tmux new -d -s v4-engine 'uv run uvicorn engine.ws:app --host 127.0.0.1 --port 8700'
bash scripts/baseline_runs.sh baseline 3
uv run python scripts/latency_breakdown.py work/runs/baseline-1 --traces work/traces --last 165 --index 0
```

初回の起動で、Kokoro の重みと OpenJTalk の辞書が自動で取得される。ブラウザのページは http://127.0.0.1:8700/ 。
